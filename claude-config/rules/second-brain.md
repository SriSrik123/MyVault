# Second Brain Rules

## Note Format

Every lecture note must follow this structure (no exceptions):

```markdown
# [Topic] — [Course Code]
**Date:** YYYY-MM-DD
**Source:** [recording filename / doc title / "in-class notes"]

## Overview
[2–4 sentence summary of what this covers and why it matters]

## Key Concepts
[Subsections for each major concept; tables and code blocks welcome]

## Important Formulas / Definitions
[Table or list of formulas, definitions, symbols]

## Summary
[3–5 sentences: what was the point, what connects to future material]
```

## Flashcard Format

When generating flashcards alongside a lecture note, save to:
`<course-folder>/flashcards/YYYY-MM-DD-<topic>-cards.md`

Each card:
```
---
**Q:** [question]
**A:** [answer]
```

## Task Tracking

- Master task list: `~/Documents/MyVault/second-brain/notes/TODO.md`
- Mark completed items with `[x]` and strikethrough (`~~text~~`)
- When adding new tasks, always include the due date and course code
- Format: `- [ ] **[Assignment name]** · due **[Day Month DD]**`

## Daily Briefing Format

Save to `~/Documents/MyVault/context/daily-logs/YYYY-MM-DD.md`:

```markdown
# Daily Briefing — [Day, Month DD YYYY]

## 🔴 Due Today / Tomorrow
[list items from TODO.md due within 24–48 hours]

## 📅 This Week
[key deadlines from TODO.md for current week]

## 🧠 Priority Focus
[1–2 sentence recommendation on what to work on first and why]

## 📚 Recent Notes
[list any lecture notes added in last 48 hours]

## ⚠️ Watch Out For
[anything that's been mentioned multiple times but not acted on,
or deadlines approaching faster than expected]
```

## Context File Update Policy

When Sri says or does something that changes his situation (new grade, completed assignment,
updated preference, new person met), update the relevant context file immediately.
Don't wait to be asked. The vault is the source of truth.
