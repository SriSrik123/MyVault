## Conventions

### Page header (every page must have this)
```yaml
---
title: <page title>
last_updated: YYYY-MM-DD
sources: [list of context files, conversation dates, or "direct"]
---
```

### Cross-referencing
Use `[[memory/entities/sri]]` style wikilinks. Every new entity or concept mentioned
in a topic page should link to its own page if one exists.

### Confidence levels
- **Confirmed** — Sri stated this directly
- **Inferred** — logically derived from other facts
- **Stale?** — may be outdated, flag for verification

### Log entry format
Each log entry starts with: `## [YYYY-MM-DD] <type> | <title>`
Types: `ingest`, `update`, `conversation`, `lint`, `setup`

## Workflows

### END OF EVERY SESSION (automatic — no need to ask)
Claude files a conversation summary without being prompted. This happens in Cowork and Claude Code.
1. Write `conversations/YYYY-MM-DD-<slug>.md` using the template below
2. Update any entity/topic pages with new facts
3. Append to `log.md`: `## [YYYY-MM-DD] conversation | <title>`
4. Update `index.md` if new pages created
5. Git commit: `memory: <title> (YYYY-MM-DD)`

**Conversation template:**
```markdown
---
title: <short title>
last_updated: YYYY-MM-DD
type: conversation
source: cowork | claude-code | manual
---
# YYYY-MM-DD — <Title>
## What Happened
## Key Decisions Made
## Facts Learned About Sri
## Tasks / Action Items Resulting
## Follow-Up Questions / Gaps
```

### Daily Briefing (on demand or scheduled)
When generating a daily briefing:
1. Create `context/daily-logs/YYYY-MM-DD.md` with today's schedule, deadlines, and priorities
2. Add back-links at the bottom: `[[second-brain/notes/TODO|TODO]]`, `[[context/semester-spring-2026|Semester Overview]]`, `[[memory/topics/academic|Academic]]`, `[[memory/index|Memory Index]]`, and prev/next day links
3. Add an entry to the Daily Logs table in `memory/index.md`
4. Append to `log.md`: `## [YYYY-MM-DD] briefing | Daily Briefing`

### When Sri shares new info about himself
1. Identify which entity/topic pages are affected
2. Update those pages with new info, noting the source and date
3. Flag any contradictions with existing content using `> ⚠️ Contradicts: ...`
4. Update `log.md`

### Periodic lint (ask Claude to run this)
- Look for stale claims that need verification
- Find entities mentioned but lacking their own page
- Check for orphan pages with no inbound links
- Suggest new questions to investigate

## project-knowledge.md — Web Claude Sync

`memory/project-knowledge.md` is a condensed snapshot of everything for **claude.ai Projects**.

Claude must update the "Memory Log" table at the bottom of `project-knowledge.md` at the end of every session — append a new row to the table. When major facts change (new job, new project, semester ends, etc.), update the relevant section of the file too.

**Sri's setup instructions for web Claude:**
1. Go to claude.ai → Projects → Create Project (name it "Sri Brain" or similar)
2. In Project Knowledge, paste the full contents of `project-knowledge.md`
3. Whenever you want to refresh it, open the file in Obsidian, copy all, replace in Project Knowledge
